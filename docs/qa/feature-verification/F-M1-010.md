## Proven vs. not proven on Apple Silicon (verbatim from Jira, not softened)

### Proven on Apple Silicon

Real accelerator discovery; vendor-neutral authorization decision; scoped
lease semantics; managed controlled launch; real Metal GPU execution on
ALLOW; managed workload non-start on DENY; local audit/explain evidence;
capability honesty.

### Not proven on Apple Silicon MVP 1.0

Arbitrary system-wide prevention of unmanaged Metal access; device-file/
kernel-level GPU isolation; retroactive GPU revoke; root/kernel attacker
resistance; Endpoint Security-based global GPU authorization.

No report, README, website, or CLI in this repository collapses these
into a generic "Protected = true" claim — see
[`APPLE_SILICON_FIXTURE.md`](../../product/APPLE_SILICON_FIXTURE.md#what-this-does-not-prove)
and [`SECURITY_MODEL.md`](../../product/SECURITY_MODEL.md#supported-platform-boundary),
both of which state this distinction independently of this record, and
were checked against the assertions above rather than merely trusted.

## Known limitations (carried forward, not silently closed)

- **This PASS does not replace F-M1-007's Linux/NVIDIA physical
  enforcement evidence requirement.** Per HORO-790's own release-gate
  definition (`docs/development/campaign-state.md`'s "Apple Silicon scope
  amendment"), an all-Apple-hardware pass is explicitly `BLOCKED ON E3`,
  never `READY`. F-M1-007 remains blocked on bare-metal Linux/NVIDIA
  hardware access, unaffected by this record.
- **No device-level GPU enforcement or revocation claim anywhere in this
  Feature.** `Capability::DeviceEnforce`/`DeviceRevoke` are `Unsupported`
  for the Apple Silicon backend on every target, unconditionally —
  verified against real discovered hardware in this pass, not just at
  the type level.
- **Never run in CI.** Every real-Metal test in `eltanin-apple` and
  `apple_metal_canonical_e2e.rs` is excluded from `.github/workflows/ci.yml`'s
  `test-macos` job (ADR 0007's decision against virtualized-GPU CI). All
  evidence in this record is real-hardware, hand-run QA evidence, not a
  standing automated gate — repeat this record's "Real hardware test
  execution" table by hand before any future release relying on it.
- **Determinism checked across a bounded number of cycles (3), not
  exhaustively** — see [`B-M1-APPLE.md`](../e2e/B-M1-APPLE.md)'s own
  "Named limitations" for the full list of scoping notes specific to that
  scenario.
- **No unmanaged-access-prevention claim.** This Feature proves the
  authorized path works and the managed denied path does not start; it
  says nothing about whether a process bypassing `eltanin run` entirely
  could dispatch Metal work directly.
